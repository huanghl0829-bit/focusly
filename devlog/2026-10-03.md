# Dev Log — 2026-10-03

## Completed
- Fixed "can't import files to the AI note page" — two independent bugs, both reproduced and verified in a headless `WKWebView` harness that drove the real sign-up → onboarding → Notes → import flow.
  - **Bug 1 (the reported symptom): the import dialog was unsubmittable for a workspace with no subjects.** `openNoteImportDialog()` leaves `#note-import-subject` empty when `currentState.subjects` is empty, and the input was `required` — so clicking **Import** triggered native HTML5 validation, which fails, blocks the `submit` event, and shows no feedback in `WKWebView`. Measured: `checkValidity() = false`, no import, no error text, dialog stays open. Fix: dropped `required` from `#note-import-subject` and `#material-import-subject` (which had the identical defect) so `submitNoteImport()`/`submitMaterialImport()` run and surface the existing in-app `.form-error` message ("Enter a subject for these notes.").
  - **Bug 2 (silent data loss): nothing was ever persisted.** Two top-level functions were both named `emptyState` — the state factory (`app.js:35`) and the empty-state HTML renderer (`app.js:120`). Function declarations hoist, so the later definition won for *every* caller and the factory was unreachable. `migrateState()`'s `{ ...emptyState(account), ... }` therefore spread an HTML string, leaving `accountId`, `tutorial`, `goals`, and `onboarding` undefined. Consequences: `persistState()` is guarded by `if (currentState?.accountId)` so it never wrote anything; `enterApp()` threw on `currentState.tutorial.completed`; and the app re-ran onboarding on every launch. Fix: renamed the factory to `createState(account)` (definition + 3 call sites). Verified no other duplicate top-level declarations remain.
  - Verified via harness: after the fix `accountId` is set, `tutorial` exists, a subject-less Import shows "Enter a subject for these notes.", importing with a subject succeeds and writes `focusly.state.v3.<id>` with `notes.length = 1`, and **after a page reload** the note, its subject, and onboarding state all survive and still render in the sandboxed `<iframe>`.
  - Also verified: `app.js` JavaScriptCore syntax OK, and `xcodebuild ... BUILD SUCCEEDED`.
